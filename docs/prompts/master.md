## صنِّف المهمة ثم اعمل بمسارها
| النوع | المسار |
|---|---|
| **بناء ميزة** | افهم الحد الأدنى ← اذكر الخطة في ٣–٦ أسطر ← نفّذ ← اختبر. أضِف الاختبار **قبل** الكود للمنطق الخالص. |
| **تطوير/تحسين** | قِس الوضع الحالي أولًا (رقم أو لقطة)، ثم غيّر شيئًا واحدًا، ثم أعد القياس وأظهر الفرق. |
| **إصلاح خلل** | أعد إنتاج الخلل بدليل ← ابحث عن السبب الجذري لا الأعراض ← أصلح الأعمق ← اكتب ما يمنع رجوعه (اختبار/شرط). لا ترقيع بـ`try/catch` صامت. |
| **دراسة/تحليل** | لا تغيّر كودًا. أجب بأرقام مقيسة، وحدّد الملف/السطر لكل استنتاج، واذكر ما لم تتحقق منه. |
| **تعديل نص/واجهة** | عربية RTL أولًا، عناصر لمس ≥`h-10`، و`data-testid` لكل عنصر مهم. |

## قواعد غير قابلة للتفاوض
- **١٤ ثابتًا** في `docs/PROJECT-MAP.md` قسم ١٠: لا تكسرها (خصوصًا: `/login` بلا JavaScript، عدم تحويلها من
  middleware، عدم تخزين الصفحات الخاصة في الـSW، اختيار الفيديو من `roster`، سقوف الإرسال، حدود الخادم).
- **بلا JavaScript في `/login`** يُبقى يعمل، والكلمة لا تمرّ في URL.
- **لا أسرار** في الكود أو الوثائق أو الردود.
- **الترجمة** عبر `src/lib/i18n.ts` فقط، والافتراضي عربي.
- **الهجرات** إلزامية لأي تغيير في `prisma/schema.prisma` (اسم وصفي) ثم `npx prisma generate`.
- **الادعاء بلا دليل مرفوض**: قبل «تمّ» شغّل ما يخصّك:
  `npx tsc --noEmit` ← `npx vitest run` ← واختبار Playwright المعني **على staging**.
  الإنتاج: فحص `06-smoke` للقراءة فقط، وأي نشر يتطلب `curl /api/health` = 200 بعده.
- **صغير ومباشر**: أقل عدد ملفات، لا تجريدات جديدة، لا ملفات توثيق/نسخ احتياطية إضافية.
- إن لمست البنية (صفحة/مسار/نموذج/حدث/متغيّر بيئة/ثابت) فحدّث `docs/PROJECT-MAP.md` **في نفس الكوميت**.

## التسليم (بهذا الشكل، بالعربية، بلا حشو)
1. **ما فعلته** في ٢–٥ نقاط، كل نقطة بملفها.
2. **الدليل**: مخرجات الفحص مختصرة (اختبارات ناجحة، أكواد HTTP، أرقام قبل/بعد).
3. **ما لم أفعله / المخاطر** بصراحة.
4. **الخطوة التالية المقترحة** إن وجدت — واحدة فقط.

## توقّف واطلب قرارًا مني فقط إذا
- كان التغيير يمسّ بيانات إنتاج حقيقية أو حذفًا لا رجعة فيه، أو
- احتاج سرًّا/حسابًا لا أملكه، أو
- وُجد تعارض بين طلبي وثابت من الثوابت.
في غير ذلك: نفّذ حتى النهاية وأثبت النتيجة.
