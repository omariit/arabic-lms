# اختبار الواجهة الآلي (Playwright)

مجموعة اختبارات تشغّل المنصة في متصفح حقيقي وتتحقّق من كل وظيفة تراها الطالبة أو المعلمة.
تعمل على **staging فقط** — وليست على الإنتاج.

## المتغيّرات

| المتغيّر | القيمة |
|---|---|
| `QA_BASE_URL` | `https://arabic-lms-staging.up.railway.app` (الافتراضي) |
| `DATABASE_URL` | قاعدة staging عبر TCP proxy: `shinkansen.proxy.rlwy.net:14090` |

## التشغيل

```bash
# 1) تهيئة بيانات الاختبار (حسابات + دورة + اختبارات + طلب تسجيل معلّق)
QA_SEED=1 DATABASE_URL="postgresql://postgres:PW@shinkansen.proxy.rlwy.net:14090/railway" \
  node prisma/seed-qa.mjs

# 2) تشغيل كل الاختبارات
QA_BASE_URL=https://arabic-lms-staging.up.railway.app npx playwright test

# 3) تقرير قابل للتنقّل (فيديو + trace + صور لكل فشل)
npx playwright show-report qa-report
```

`npm run qa` = نفس الأمر الثالث المختصر، و`npm run qa:seed` للتهيئة.

| الملف | التغطية |

| `02-auth.spec.ts` | دخول المعلمة والطالبة، كلمة مرور خاطئة، كوكي مُلفَّق، **انتهاء الجلسة أثناء العمل → شاشة ودّية**، خروج، حدود الأدوار |
| `03-student.spec.ts` | اللوحة، الدرس (وصف/سكربت/واجب)، تسليم نصي، **تسجيل واجب صوتي واستماعه**، محادثة نصية + **رسالة صوتية**، رفع صوت عبر الـ API والتحقّق من الصلاحيات، اختبار MCQ كامل، طلب تسجيل مع صورة إيصال |
| `04-teacher.spec.ts` | لا أخطاء API في اللوحة، تحميل القوائم تلقائيًا، محرر الدورة (المخرجات/المتطلبات)، الموافقة على طلب تسجيل، طابور التصحيح، صندوق واجبات الدرس، إنشاء مساعدة ودخولها فعليًا، آراء الطالبات، الكوبونات، CMS الصفحة الرئيسية والنشر، إعدادات الدفع، رفع الغلاف والمرفقات + رفض المفاتيح المزوّرة |
| `05-meeting.spec.ts` | إنشاء حصة داخلية، غرفة المعلمة، **ضيفة عبر رابط عام → طلب دخول → قبول**، إسكات المايك/إيقاف الكاميرا/رفع اليد، دردشة الحصة، إنهاء الحصة، دخول طالبة مسجّلة |

## مبادئ

- **لا حقن كوكيز**: كل اختبار يسجّل الدخول من نموذج الدخول الحقيقي.
- **الرفع يمرّ بنفس مسار الواجهة**: presign → PUT إلى R2 → الطلب النهائي، تمامًا كما يفعل المتصفح.
- **كل فشل يُحفظ**: صورة + فيديو + trace في `qa-report/`.
- الاختبارات ملفوفة بـ `retries: 1` لأن Railway قد يبرد (cold start)؛ الفشل المتكرر يعني خللًا حقيقيًا.
- الحسابات: `0790000001..6` بكلمة مرور `qa-pass-2026` (staging فقط).

## فحص الإنتاج (قراءة فقط، لا يلمس البيانات)

```bash
QA_SMOKE=1 SMOKE_TEACHER_PASSWORD="..." QA_BASE_URL=https://arabic-lms-production.up.railway.app npm run qa:smoke
```

يفتح كل شاشات لوحة المعلمة على الإنتاج ويفشل إذا ظهر أي طلب API مرفوض أو خطأ صفحة —
هذا هو الفحص الذي يمنع تكرار مشكلة «401 في كل مكان» من الوصول للمستخدمات.

## كلمات المرور وتغييرها

- **الطالبة**: المعلمة/الإدارة تفتح **/admin/students** → «تعيين كلمة مرور» → يُقترح مقترح جاهز
  (`Sara-Quran-3481`) مع زر نسخ، ويُنهي الحفظ كل جلساتها المفتوحة.
- **الأدمن/المعلمة**: تُحدَّث من سكربت `prisma/set-staff.mjs` (يمسح الجلسات القديمة).
- صفحة الدخول تتعافى تلقائيًا من أخطاء الكتابة الشائعة: الأرقام العربية (٠٧٨…)، الشُرَط الذكية
  (– —)، والمسافات غير المرئية — في الرقم وكلمة المرور معًا. مغطّى بـ
  `tests/login-input.test.ts` و`tests/e2e/02-auth.spec.ts`.

## سلوك تسجيل الدخول (بعد إصلاح 2026-11)

- **الحدّ الأمني يحسب المحاولات الفاشلة فقط** (`login-fail:<ip>:<phone>` = 8 في الدقيقة، ثم
  توقّف مؤقت مع عدّاد ثوانٍ). تسجيل دخول ناجح يصفّر العدّاد، لذلك **لا يمكن للمستخدم أن يقفل
  نفسه** بتجربة كلمة المرور الصحيحة عدة مرات (كان هذا سبب «بيقول خطأ» عند الاختبار المتكرر).
- سقف إضافي لكل IP على المحاولات الفاشلة (60/دقيقة) ضد تخمين أرقام متعددة من نفس الجهاز.
- رسائل دقيقة: «لا يوجد حساب بهذا الرقم» مقابل «كلمة المرور غير صحيحة — تبقّى N محاولة»،
  مع سطر تشخيصي في سجلات الخادم: `[login] failure phone=… found=… passwordMatch=… attemptsLeft=…`
  (بلا كلمة المرور أبدًا).
- إدخال مرن: أرقام عربية (٠٧٨…)، شُرَط ذكية (– —)، مسافات، `+962…`، `00962…`، `962…`، والرقم
  بلا الصفر (787262186).
- زر «إظهار» لكلمة المرور + تنبيه إن وُجدت مسافة في الأطراف.
- بيئة staging تعرض شارة «بيئة تجريبية» في صفحة الدخول حتى لا تُخلط بالإنتاج.
